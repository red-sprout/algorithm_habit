# Stack

## 스택이란?

스택(Stack)은 **가장 나중에 넣은 데이터를 가장 먼저 꺼내는** 선형 자료구조입니다. 이 규칙을 LIFO(Last In, First Out)라고 합니다.

접시를 쌓아 두는 모습을 떠올리면 쉽습니다. 새 접시는 맨 위에 놓고, 꺼낼 때도 맨 위 접시부터 꺼냅니다. 중간 접시를 바로 꺼내거나 맨 아래에 새 접시를 넣는 일은 스택의 기본 연산에 포함하지 않습니다.

스택에서 데이터를 넣고 꺼내는 쪽을 `top`이라고 합니다. `top`은 가장 최근에 넣은 원소를 가리킵니다.

```
top
 ↓
[ C ][ B ][ A ]
```

위 스택에 `D`를 넣으면 `D`가 top이 되고, 하나를 꺼내면 `D`가 나옵니다.

## 핵심 연산

- `push(x)`: `x`를 top에 넣습니다.
- `pop()`: top 원소를 제거하고 반환합니다.
- `peek()` 또는 `top()`: top 원소를 제거하지 않고 확인합니다.
- `isEmpty()`: 스택이 비어 있는지 확인합니다.
- `size()`: 저장된 원소 수를 반환합니다.

연산 흐름은 다음과 같습니다.

```
Empty
push(A) → [ A ]
push(B) → [ B ][ A ]
push(C) → [ C ][ B ][ A ]
pop()   → return C, [ B ][ A ]
peek()  → return B, [ B ][ A ]
```

비어 있는 스택에 `pop()`이나 `peek()`를 호출하면 꺼낼 원소가 없습니다. 이를 **underflow(언더플로)** 라고 하며, 문제 풀이에서는 호출 전에 비어 있는지 확인해야 합니다.

## 추상 자료형과 구현

스택은 "어떤 규칙으로 데이터를 다룰지"를 정의하는 **추상 자료형(ADT)** 입니다. 배열과 연결 리스트는 그 규칙을 실제 메모리에 구현하는 방법입니다.

### 배열 기반 구현

배열의 끝을 top으로 사용합니다. 배열은 원소를 연속된 메모리 칸에 저장하므로, top의 인덱스만 알면 마지막 원소에 바로 접근할 수 있습니다. 많은 언어의 동적 배열은 이 방식으로 스택을 구현하기 좋습니다.

다음은 용량이 5인 배열 스택입니다. `top`은 마지막 원소의 인덱스이며, 빈 스택에서는 `-1`입니다.

```
index |  0  |  1  |  2  |  3  |  4  |
      +-----+-----+-----+-----+-----+
value |     |     |     |     |     |
      +-----+-----+-----+-----+-----+
top = -1
```

`push(A)`는 `top`을 하나 증가시킨 뒤 그 칸에 `A`를 저장합니다.

```
1. top ← top + 1
   top = 0

2. array[top] ← A
index |  0  |  1  |  2  |  3  |  4  |
      +-----+-----+-----+-----+-----+
value |  A  |     |     |     |     |
      +-----+-----+-----+-----+-----+
        ↑
       top
```

같은 방식으로 `push(B)`, `push(C)`를 수행합니다. 기존 원소를 옮기지 않고 빈 칸에 새 원소만 저장합니다.

```
push(B)
index |  0  |  1  |  2  |  3  |  4  |
      +-----+-----+-----+-----+-----+
value |  A  |  B  |     |     |     |
      +-----+-----+-----+-----+-----+
              ↑
             top

push(C)
index |  0  |  1  |  2  |  3  |  4  |
      +-----+-----+-----+-----+-----+
value |  A  |  B  |  C  |     |     |
      +-----+-----+-----+-----+-----+
                    ↑
                   top
```

`peek()`는 `array[top]`을 읽기만 하므로 배열과 top이 바뀌지 않습니다.

```
peek() → return C

index |  0  |  1  |  2  |  3  |  4  |
      +-----+-----+-----+-----+-----+
value |  A  |  B  |  C  |     |     |
      +-----+-----+-----+-----+-----+
                    ↑
                   top
```

`pop()`은 먼저 `array[top]`의 값 `C`를 기억하고, 그 칸을 비운 뒤 `top`을 하나 감소시킵니다. `C` 뒤에 있던 원소를 앞으로 옮길 필요가 없습니다.

```
1. x ← array[top] = C

2. clear array[top]; top ← top - 1
index |  0  |  1  |  2  |  3  |  4  |
      +-----+-----+-----+-----+-----+
value |  A  |  B  |     |     |     |
      +-----+-----+-----+-----+-----+
              ↑
             top

3. return C
```

고정 크기 배열에서 `top = 4`인 상태로 `push`하면 빈 칸이 없어 overflow가 발생합니다. 동적 배열은 보통 더 큰 배열을 만들고 기존 원소를 복사한 뒤 새 원소를 저장합니다. 이 복사가 필요한 한 번의 `push`는 O(n)이지만, 매 삽입마다 일어나지는 않습니다.

```
before: capacity = 3
      +-----+-----+-----+
value |  A  |  B  |  C  |
      +-----+-----+-----+
top = 2

after: capacity = 6
      +-----+-----+-----+-----+-----+-----+
value |  A  |  B  |  C  |  D  |     |     |
      +-----+-----+-----+-----+-----+-----+
top = 3
```

배열 스택에서는 `top = -1`인지 확인해 빈 스택을 판별합니다. 원소 수는 `top + 1`이므로 별도로 셀 필요가 없습니다.

```
isEmpty()
top = -1 → true
top =  2 → false

size()
top = 2 → 2 + 1 = 3
```

- 장점: 원소가 연속된 메모리에 있어 접근이 빠르고 구현이 간단합니다.
- 주의: 고정 크기 배열은 용량을 넘으면 overflow가 발생합니다. 동적 배열은 공간이 부족할 때 더 큰 배열로 옮기는 재할당이 한 번 일어날 수 있습니다.

### 연결 리스트 기반 구현

연결 리스트의 머리(head)를 top으로 사용합니다. 각 노드는 값과 다음 노드의 위치를 가리키는 `next`를 함께 저장합니다. 노드들이 연속된 메모리에 있을 필요는 없습니다.

빈 스택에서는 `top`이 어떤 노드도 가리키지 않는 `null`입니다.

```
top
 ↓
null
```

`push(A)`는 새 노드를 만든 뒤, 새 노드의 `next`가 기존 top을 가리키게 하고 top을 새 노드로 바꿉니다.

```
1. create node
   new = [ A | null ]

2. new.next ← top
   new = [ A | null ]       top → null

3. top ← new
   top
    ↓
   [ A | null ]
```

`push(B)`, `push(C)`도 같은 절차를 반복합니다. 항상 새 노드를 가장 앞에 연결하므로, 가장 최근에 넣은 원소가 top입니다.

```
push(B)
top
 ↓
[ B |  • ] ───→ [ A | null ]

push(C)
top
 ↓
[ C |  • ] ───→ [ B |  • ] ───→ [ A | null ]
```

`peek()`는 top 노드의 값만 읽습니다. 연결 관계와 top은 바뀌지 않습니다.

```
peek() → return C

top
 ↓
[ C |  • ] ───→ [ B |  • ] ───→ [ A | null ]
```

`pop()`은 top 노드의 값 `C`를 기억하고, top을 그 노드의 다음 노드로 옮깁니다. 이전 top 노드는 더 이상 스택에서 참조되지 않으며, 언어 또는 실행 환경의 방식에 따라 메모리가 해제됩니다.

```
1. x ← top.value = C

2. top ← top.next
top
 ↓
[ B |  • ] ───→ [ A | null ]

3. old node [ C | • ] disconnected
4. return C
```

연결 리스트는 새 노드 하나만 만들 수 있다면 `push`할 수 있으므로 고정 용량으로 인한 overflow는 없습니다. 다만 메모리가 부족하면 새 노드를 만들 수 없으므로 삽입할 수 없습니다.

연결 리스트 스택도 `top = null`인지 확인해 비어 있는지 판단합니다. `size()`를 O(1)에 처리하려면 원소 수를 별도 변수로 저장하고 `push`마다 1 증가, `pop`마다 1 감소시켜야 합니다. 이 변수가 없다면 모든 노드를 세어야 하므로 `size()`는 O(n)입니다.

```
isEmpty()
top → null                 → true
top → [ B | • ] → ...      → false

with stored size
push(A): size 0 → 1
push(B): size 1 → 2
pop():   size 2 → 1
```

- 장점: 미리 최대 크기를 정할 필요가 없습니다.
- 단점: 각 원소에 다음 노드를 가리키는 참조 공간이 추가로 필요하고, 원소가 흩어진 메모리에 있어 실제 실행에서는 배열보다 불리할 수 있습니다.

중요한 점은 배열의 `0`번 인덱스에 넣고 빼는 구현은 피해야 한다는 것입니다. 앞쪽 삽입·삭제는 나머지 원소들을 모두 옮겨야 하므로 O(n)이 됩니다. 배열 스택은 끝을 top으로 써야 합니다.

## 시간·공간 복잡도

| 연산 | 배열 기반 | 연결 리스트 기반 | 이유 |
| --- | --- | --- | --- |
| `push` | 평균 O(1), 최악 O(n) | O(1) | 배열은 가끔 재할당·복사가 필요하고, 연결 리스트는 top 앞에 노드 하나를 연결합니다. |
| `pop` | O(1) | O(1) | top 위치 또는 머리 노드만 변경합니다. |
| `peek` | O(1) | O(1) | top 원소 하나만 확인합니다. |
| `isEmpty`, `size` | O(1) | O(1)·원소 수 저장 시 | 배열은 top을, 연결 리스트는 top과 저장한 원소 수를 바로 확인합니다. |
| 전체 저장 공간 | O(n) | O(n) | 원소가 n개일 때 n개를 저장합니다. |

동적 배열의 `push`는 재할당 순간에는 O(n)이지만, 충분히 큰 공간을 확보해 두면 이후 여러 번의 삽입은 O(1)입니다. 따라서 연속된 많은 `push`의 평균 비용, 즉 **상환 시간 복잡도(amortized complexity)** 는 O(1)입니다. 이는 모든 한 번의 `push`가 항상 O(1)이라는 뜻은 아닙니다.

## 의사코드

배열의 끝을 top으로 쓰는 스택은 다음처럼 표현할 수 있습니다.

```
procedure PUSH(S, x)
    append x to S

procedure POP(S)
    if S is empty
        report underflow
    x ← last element of S
    remove last element of S
    return x

procedure PEEK(S)
    if S is empty
        report underflow
    return last element of S

procedure IS_EMPTY(S)
    return (number of elements in S = 0)
```

## Python

파이썬에서는 내장 `list`를 스택으로 사용합니다. 리스트의 끝에 추가하고 끝에서 제거하므로 `append()`와 `pop()`이 스택의 `push`, `pop`에 각각 대응합니다.

```python
stack = []

stack.append("A")
stack.append("B")

top = stack[-1]
item = stack.pop()

is_empty = not stack
size = len(stack)
```

`stack[-1]`과 `stack.pop()`은 스택이 비어 있으면 `IndexError`가 발생합니다. 따라서 빈 스택일 수 있는 경우에는 `if stack:`으로 먼저 확인합니다. `list.pop(0)`은 앞쪽 원소를 제거한 뒤 나머지 원소를 옮기므로 스택 구현에 사용하지 않습니다.

## 언제 쓰는가

스택은 최근 상태부터 되돌리거나, "열어 둔 작업을 닫는 순서"를 추적할 때 자연스럽습니다.

- 괄호 짝 검사: 여는 괄호를 넣고 닫는 괄호가 나오면 가장 최근 괄호와 짝이 맞는지 확인합니다.
- 문자열·수열 뒤집기: 넣은 순서의 반대로 꺼냅니다.
- 되돌리기(undo): 가장 최근 작업부터 취소합니다.
- 함수 호출 관리: 프로그램 실행 환경은 호출한 함수의 정보를 스택 형태로 관리합니다.
- 깊이 우선 탐색(DFS): 재귀 호출은 내부적으로 호출 스택을 사용하며, 반복문으로 구현할 때도 명시적인 스택을 쓸 수 있습니다. 이는 이후 그래프 탐색에서 다룹니다.

## 자주 하는 실수

- `pop` 전에 빈 스택을 확인하지 않아 underflow를 일으킵니다.
- 배열 앞쪽을 top으로 사용해 `push`와 `pop`이 O(n)이 되게 만듭니다.
- 괄호 문제에서 닫는 괄호를 만났을 때 스택이 비어 있는 경우를 놓칩니다.
- 모든 입력을 처리한 뒤에도 스택에 여는 괄호가 남아 있는 경우를 놓칩니다.
- 스택의 순서를 뒤집어 이해합니다. 스택을 순회하거나 출력할 때 보이는 저장 순서와 실제 `pop` 순서를 구분해야 합니다.

## 핵심 정리

스택은 top 한쪽에서만 삽입과 삭제를 수행해 LIFO를 보장합니다. 이 제약 덕분에 최근 원소의 추가·제거를 O(1)에 처리할 수 있습니다. 문제에서 "가장 최근", "되돌리기", "짝 맞추기"가 보이면 스택을 먼저 떠올려 봅시다.

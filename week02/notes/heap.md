# Heap

## 힙이란?

힙(Heap)은 **완전 이진 트리(complete binary tree)** 형태를 유지하면서, 부모와 자식 사이에 정해진 우선순위 규칙을 만족하는 자료구조입니다.

- **최소 힙(min heap)**: 모든 부모의 값이 자식의 값보다 작거나 같습니다. 따라서 루트에 최솟값이 있습니다.
- **최대 힙(max heap)**: 모든 부모의 값이 자식의 값보다 크거나 같습니다. 따라서 루트에 최댓값이 있습니다.

완전 이진 트리는 마지막 레벨을 제외한 모든 레벨이 채워져 있고, 마지막 레벨의 원소는 왼쪽부터 빈칸 없이 채워진 트리입니다. 이 모양 덕분에 힙은 포인터 없이 배열로 효율적으로 표현할 수 있습니다.

이 노트에서는 최솟값을 빠르게 꺼내는 **최소 힙**을 기준으로 설명합니다. 최대 힙도 비교 방향만 반대로 바꾸면 같은 방식으로 동작합니다.

```
              1
           /     \
          3       5
        /  \     /  \
       7    8   6    9
```

위 트리는 부모가 자식보다 작으므로 최소 힙입니다. 다만 힙은 전체가 정렬된 구조가 아닙니다. 예를 들어 `7`과 `6`의 상대적인 크기나 위치는 힙 규칙으로 정해지지 않습니다.

## 핵심 연산

- `insert(x)`: 새 원소 `x`를 힙에 넣습니다.
- `peek()`: 루트 원소를 제거하지 않고 확인합니다.
- `extractMin()`: 최소 힙의 루트, 즉 최솟값을 제거하고 반환합니다.
- `isEmpty()`: 힙이 비어 있는지 확인합니다.
- `size()`: 저장된 원소 수를 반환합니다.

최소 힙의 루트는 항상 최솟값이므로 `peek()`는 O(1)입니다. 반면 삽입 또는 루트 삭제 뒤에는 힙 규칙을 다시 맞춰야 합니다.

## 배열로 표현하는 완전 이진 트리

0번 인덱스부터 저장하는 배열에서 어떤 노드의 인덱스가 `i`라면 다음 관계가 성립합니다.

| 대상 | 인덱스 |
| --- | --- |
| 부모 | `(i - 1) // 2` (`i > 0`) |
| 왼쪽 자식 | `2i + 1` |
| 오른쪽 자식 | `2i + 2` |

예를 들어 다음 트리는 배열 `[1, 3, 5, 7, 8, 6, 9]`로 저장됩니다. 같은 레벨에서는 왼쪽에서 오른쪽 순서로 배열에 들어갑니다.

```
tree
              1
           /     \
          3       5
        /  \     /  \
       7    8   6    9

array
index |  0  |  1  |  2  |  3  |  4  |  5  |  6  |
      +-----+-----+-----+-----+-----+-----+-----+
value |  1  |  3  |  5  |  7  |  8  |  6  |  9  |
      +-----+-----+-----+-----+-----+-----+-----+
```

배열은 연속된 메모리에 원소를 저장합니다. 마지막 위치에 새 원소를 추가하거나 마지막 원소를 제거하는 일은 빠르며, 인덱스 계산만으로 부모·자식을 찾을 수 있습니다. 그래서 힙은 보통 배열로 구현합니다.

## 삽입: sift-up

최소 힙에 원소를 삽입할 때는 먼저 배열의 마지막, 즉 트리의 다음 빈자리에 넣습니다. 완전 이진 트리 모양을 먼저 유지한 뒤, 부모보다 값이 작으면 부모와 교환하면서 위로 올립니다. 이 과정을 **sift-up** 또는 **bubble-up**이라고 합니다.

다음 최소 힙에 `2`를 삽입해 보겠습니다.

```
before insert
              1
           /     \
          3       5
        /  \     /
       7    8   6
```

먼저 마지막 위치에 `2`를 넣습니다. 아직 `2`의 부모는 `5`이므로 힙 규칙이 깨져 있습니다.

```
append 2
              1
           /     \
          3       5
        /  \     / \
       7    8   6   2

array
index |  0  |  1  |  2  |  3  |  4  |  5  |  6  |
      +-----+-----+-----+-----+-----+-----+-----+
value |  1  |  3  |  5  |  7  |  8  |  6  |  2  |
      +-----+-----+-----+-----+-----+-----+-----+
```

`2 < 5`이므로 `2`와 `5`를 교환합니다. 이제 `2`의 부모는 `1`이고 `1 ≤ 2`이므로 멈춥니다.

```
after sift-up
              1
           /     \
          3       2
        /  \     / \
       7    8   6   5

array
index |  0  |  1  |  2  |  3  |  4  |  5  |  6  |
      +-----+-----+-----+-----+-----+-----+-----+
value |  1  |  3  |  2  |  7  |  8  |  6  |  5  |
      +-----+-----+-----+-----+-----+-----+-----+
```

원소는 한 번 교환할 때마다 한 레벨 위로 이동합니다. 높이가 O(log n)이므로 sift-up의 최악 시간 복잡도는 O(log n)입니다.

## 최솟값 제거: sift-down

`extractMin()`은 루트의 최솟값을 반환해야 합니다. 루트를 바로 비우면 트리의 중간에 빈자리가 생기므로, 마지막 원소를 루트로 옮긴 뒤 마지막 칸을 제거합니다. 이후 자식 중 더 작은 값과 교환하며 아래로 내립니다. 이 과정을 **sift-down** 또는 **bubble-down**이라고 합니다.

다음 최소 힙에서 `extractMin()`을 수행합니다.

```
before extractMin()
              1
           /     \
          3       2
        /  \     / \
       7    8   6   5
```

루트 `1`을 기억하고 마지막 원소 `5`를 루트로 옮깁니다. `5`는 자식 `3`, `2`보다 크므로 아직 최소 힙이 아닙니다.

```
move last value to root
              5
           /     \
          3       2
        /  \     /
       7    8   6
```

두 자식 중 더 작은 `2`와 `5`를 교환합니다. `5`의 새 자식은 `6` 하나이고 `5 ≤ 6`이므로 sift-down을 멈춥니다.

```
after sift-down
              2
           /     \
          3       5
        /  \     /
       7    8   6

array
index |  0  |  1  |  2  |  3  |  4  |  5  |
      +-----+-----+-----+-----+-----+-----+
value |  2  |  3  |  5  |  7  |  8  |  6  |
      +-----+-----+-----+-----+-----+-----+

return 1
```

항상 두 자식 중 더 작은 자식과 교환해야 합니다. 큰 자식과 교환하면 다른 자식보다 부모가 커져 힙 규칙이 계속 깨질 수 있습니다.

## 힙의 구현과 선택

힙은 보통 배열로 구현합니다. 완전 이진 트리의 빈틈없는 모양 덕분에 배열의 빈칸이 거의 없고, 부모·자식을 인덱스로 바로 찾을 수 있기 때문입니다.

연결 리스트로도 트리를 만들 수는 있지만, 다음 삽입 위치를 찾으려면 별도 정보나 탐색이 필요합니다. 또한 각 노드에 자식 참조가 필요해 배열 구현보다 단순하지 않습니다. 따라서 일반적인 우선순위 큐에는 배열 기반 이진 힙이 적합합니다.

힙은 **우선순위 큐(priority queue)** 를 구현하는 대표적인 방법입니다. 우선순위 큐는 "가장 높은 우선순위 원소를 먼저 꺼낸다"는 기능을 제공하고, 힙은 이를 효율적으로 구현하는 내부 자료구조입니다.

## 시간·공간 복잡도

| 연산 | 시간 복잡도 | 이유 |
| --- | --- | --- |
| `peek` | O(1) | 루트는 배열의 0번 인덱스에 있습니다. |
| `insert` | O(log n) | 새 원소가 트리 높이만큼 위로 이동할 수 있습니다. |
| `extractMin` | O(log n) | 마지막 원소가 트리 높이만큼 아래로 이동할 수 있습니다. |
| `isEmpty`, `size` | O(1) | 배열 길이 또는 저장한 원소 수를 바로 확인합니다. |
| 임의 원소 탐색 | O(n) | 힙은 전체 정렬이 아니므로 모든 원소를 확인할 수 있습니다. |
| 전체 저장 공간 | O(n) | 원소가 n개일 때 n개를 저장합니다. |

배열이 충분한 용량을 확보하지 못하면 삽입 중 재할당과 복사가 일어날 수 있습니다. 이 한 번의 복사는 O(n)이지만, 동적 배열의 확장 정책에 따라 많은 삽입에 대한 상환 비용은 보통 O(1)입니다. 이는 sift-up에 필요한 O(log n) 비용과는 별개의 구현 비용입니다.

## 의사코드

다음은 0번 인덱스부터 저장하는 최소 힙의 의사코드입니다.

```
procedure INSERT(H, x)
    append x to H
    i ← H.size - 1
    while i > 0 and H[parent(i)] > H[i]
        swap H[parent(i)], H[i]
        i ← parent(i)

procedure EXTRACT_MIN(H)
    if H is empty
        report underflow
    minimum ← H[0]
    H[0] ← last element of H
    remove last element of H
    i ← 0
    while H has a child at i
        child ← index of smaller child of i
        if H[i] ≤ H[child]
            break
        swap H[i], H[child]
        i ← child
    return minimum

procedure PEEK(H)
    if H is empty
        report underflow
    return H[0]

procedure PARENT(i)
    return (i - 1) // 2
```

## Python

파이썬의 표준 라이브러리 `heapq`는 리스트를 **최소 힙**으로 다룹니다. `heappush()`로 삽입하고 `heappop()`으로 최솟값을 꺼냅니다. 힙의 최솟값을 확인만 할 때는 리스트의 0번 인덱스를 읽습니다.

```python
import heapq

heap = []

heapq.heappush(heap, 3)
heapq.heappush(heap, 1)
heapq.heappush(heap, 2)

minimum = heap[0]
item = heapq.heappop(heap)

values = [3, 1, 2]
heapq.heapify(values)
```

힙 리스트를 그대로 출력하면 정렬된 결과가 아니라 **힙의 내부 배열 상태**가 출력됩니다. `heap[0]`만 항상 최솟값이며, 나머지 원소의 순서는 정렬되어 있지 않습니다. 정렬된 결과가 필요하고 원래 힙을 유지해야 한다면 `sorted()`를 사용합니다. 힙을 소모해도 된다면 `heappop()`을 반복합니다.

```python
heap = [3, 1, 5, 2]
heapq.heapify(heap)

print(heap)
ordered = sorted(heap)

while heap:
    print(heapq.heappop(heap))
```

숫자 최대 힙이 필요하면 값을 음수로 넣고 꺼낼 때 다시 음수로 바꿉니다. 빈 힙에 `heap[0]` 또는 `heappop()`을 호출하면 `IndexError`가 발생하므로 `if heap:`으로 먼저 확인합니다.

```python
max_heap = []

heapq.heappush(max_heap, -3)
heapq.heappush(max_heap, -1)

largest = -heapq.heappop(max_heap)
```

## 언제 쓰는가

힙은 전체 원소를 정렬할 필요는 없지만, 매번 가장 작거나 큰 원소를 빠르게 꺼내야 할 때 적합합니다.

- 작업 스케줄링: 우선순위가 높은 작업을 먼저 처리합니다.
- 여러 정렬된 데이터의 병합: 각 데이터의 현재 최솟값을 힙에 넣어 가장 작은 값을 반복해서 꺼냅니다.
- 상위 K개 원소 유지: 크기 K의 힙으로 필요한 후보만 유지합니다.
- 다익스트라 알고리즘: 가장 짧은 후보 거리를 빠르게 선택하기 위해 우선순위 큐를 사용합니다. 이는 이후 그래프 단원에서 다룹니다.

## 자주 하는 실수

- 힙이 전체 정렬된 배열이라고 생각합니다. 힙은 부모와 자식 관계만 보장합니다.
- 최소 힙에서 `extractMin()` 뒤 마지막 원소를 루트로 옮기지 않아 완전 이진 트리 모양을 깨뜨립니다.
- sift-down에서 두 자식 중 더 작은 자식이 아니라 임의의 자식과 교환합니다.
- 배열 인덱스가 0부터인지 1부터인지 섞어 부모·자식 공식을 틀립니다.
- 비어 있는 힙의 루트를 확인하거나 제거합니다.

## 핵심 정리

힙은 완전 이진 트리와 부모·자식 우선순위 규칙을 결합한 자료구조입니다. 최소 힙은 최솟값을 O(1)에 확인하고 O(log n)에 제거할 수 있으므로, 우선순위가 가장 높은 원소를 반복해서 처리하는 문제에 적합합니다.
